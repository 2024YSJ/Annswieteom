## 배경

24번이 피드 백엔드를 끝내면서 남은 작업에 이렇게 적었다: "**프론트 연동 전체.**
⚠️ `app/page.tsx`가 세션이 1개 이상인 로그인 사용자를 곧바로 최근 세션으로
리다이렉트한다 — 프로필이 쌓인 바로 그 사용자가 랜딩을 못 본다."

그게 이번 작업의 전부다. 엔드포인트 3개(`/feed/policies`, `/feed/jobs`,
`/feed/jobs/recommended`)는 실 데이터까지 검증돼 있었지만 화면이 없었다.

## 완료 항목

- `lib/api/feed.ts` + 쿼리 키 `feed(scope)` + 배럴 재수출.
- `components/FeedSection.tsx` — 섹션 하나를 통째로 담당한다(조회·상태·카드).
- `app/page.tsx` 재구성 — 히어로 / 이어서 하기 / 플로우 카드 / 맞춤 공고 /
  최신 공고 / 청년 지원 정책 / 예시 문서.
- 아카이브·커버리지 화면을 19번의 디자인 시스템 토큰에 맞춰 정리.
- 기록물 첨부 주석에 남아 있던 "image" 표현 제거(23번에서 이미지 OCR이 빠졌다).
- e2e 3곳 갱신 + `workers: 1` 고정(아래).

## 핵심 결정 사항과 이유

**자동 리다이렉트를 없애고 "이어서 하기"로 대체했다.** 리다이렉트가 살아 있으면
맞춤 공고는 **구조적으로 도달 불가능**하다 — 개인화는 문답이 쌓인 사용자에게만
의미가 있는데, 그 사용자가 정확히 리다이렉트 대상이다. 로고를 눌러도 세션으로
되돌아와서 홈이라는 화면 자체가 없었다. 대신 최근 세션 3개를 카드로 띄워서
한 번의 클릭은 그대로 보장한다. 결과적으로 예전보다 기능이 하나 늘었다.

**맞춤 공고가 개인화되지 않았을 때는 목록을 아예 그리지 않는다.** 서버는 프로필이
없어도 오류 대신 최신순 + `fallback_reason`으로 응답하는데, 그 목록은 바로 아래
"최신 공고"와 **글자 그대로 같다.** 처음 붙였을 때 같은 카드 6장이 화면에 두 번
나왔다. 지금은 그 자리에 왜 아직 맞춤이 아닌지와 다음에 뭘 하면 되는지만 남긴다.

**`fallback_reason` 세 가지를 각각 다른 문구로 처리했다.** 서버가 굳이 셋으로 나눈
이유(24번 트러블슈팅: 정상 사용자에게 "AI 서버가 수리 중"이 떴던 일)를 프론트에서
다시 뭉개면 그 분리가 무의미해진다. `no_profile`은 권유, `preparing`은 대기 안내,
`ai_unavailable`만 고장 안내(`.msg-error`)로 쓴다.

**`is_warming`일 때만 폴링한다.** 캐시가 비면 서버가 수집을 예약하고 응답 이후에
돌리므로 최초 1회는 구조적으로 빈 응답이 온다. `refetchInterval`을 응답값에
연동해서, 캐시가 차는 순간 `false`가 되어 폴링이 스스로 멈춘다 — 메인 화면을
열어둔 채로 요청이 계속 나가지 않는다.

**`detail_url`이 없는 카드는 `<a>`가 아니라 `<div>`다.** 워크넷 6개 카테고리 중
상세 URL을 안 주는 것이 실제로 있다. 눌리는 것처럼 보이는데 아무 일도 없으면 안
된다.

**한국어 라벨을 프론트에 하드코딩하지 않았다.** `source_label`/`category_label`은
라우터가 채워서 내려준다. 카테고리가 늘어도 프론트를 안 고쳐도 된다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| e2e 8개 중 3개가 실행할 때마다 다른 조합으로 실패. 개별 실행은 전부 통과 | Playwright 기본 워커 수가 CPU/2라 8개가 병렬로 돌면서 **백엔드 한 대 + Next dev 서버 한 대**를 두고 경쟁했다 | `playwright.config.ts`에 `workers: 1`. 전체가 1.5분이라 병렬로 얻을 게 없다. 이전부터 있던 문제이고, 19번에서 "session-flow가 전체 실행 시 timeout"으로 보고했던 것의 진짜 원인이다 |
| 홈에서 `getByText("...님")`이 3개 요소에 매칭 | 히어로가 "{닉네임}님, 이어서 해볼까요?"로 바뀌면서 헤더 span·h1·route announcer 셋이 같은 문자열을 품게 됐다 | 테스트를 `exact: true`로 좁혔다 |
| 브라우저 검증 중 `main-app.js`가 영원히 pending이라 페이지가 하이드레이션되지 않음 | 오래 띄워둔 webpack dev 서버가 물린 것. 앱 문제가 아니다 | dev 서버 재시작. 판단 근거는 요청 목록을 찍어서 확인했다(추측으로 코드를 고치지 않았다) |

## 검증

- `tsc --noEmit` / `eslint` / `next build --webpack` 클린.
- **e2e 8/8 통과**(직렬). 19번 시점의 "전체 실행 시 1개 실패"가 해소됐다.
- 실 백엔드 + 실 워크넷 캐시로 브라우저 확인: 로그아웃 랜딩(공고 6 + 정책 6 실
  데이터), 게스트 로그인 후 홈(이어서 하기 + 맞춤 공고 `no_profile` 안내),
  `/archive` 빈 상태, 모바일 1열.

## 남은 작업

- **`personalized: true` 화면을 브라우저로 못 봤다.** 문답을 쌓고 임베딩이 돌아야
  하는데 로컬에서 그 상태를 만들려면 인터뷰를 끝까지 진행해야 한다. 백엔드는
  24번에서 계정 두 개로 실측했으므로 데이터 경로는 확인됐고, 미확인인 건 "맞춤"
  배지가 붙은 화면의 렌더링뿐이다.
- 피드에 페이지네이션이 없다. `limit=6`으로 잘라 보여주고 "더보기"가 없다 —
  API는 `offset`을 받으므로 붙이는 건 어렵지 않다.
- 카테고리 필터(`?category=`)도 API에만 있고 화면에는 없다. 레퍼런스 사이트처럼
  칩으로 거르는 UI가 다음 후보다.
- devlog 번호가 갈라졌다: `worktree-sidebar-wrap-and-llm-harness` 브랜치에도
  19·20번이 따로 있다(`19_llm_sampling_context_and_fewshot.md`,
  `20_job_search_hang_and_unfiltered_retrieval.md`). 병합할 때 한쪽을 다시
  번호 매겨야 한다.
