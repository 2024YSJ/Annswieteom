# 47. 직업 키워드 동의어 테이블 실계정 검증 및 보강 (2026-09-15)

devlog 46(직업 키워드 동의어 확장) 배포 직후, `job_fair`/`training_course`
재현율이 실제로 개선됐는지 확인하고 테이블을 보강하기 위해 다양한 직업으로
실계정 세션을 여러 개 진행했다.

## 배포 중 발견한 회귀

첫 재현 시도("경남 용접공 채용행사")가 여전히 `skipped`로 나왔다. 원인:
`search_job_fairs`가 표현 3개(용접공/용접/용접기능사)를 `asyncio.gather`로
동시 조회하는데, 고용24는 "이 키워드로 매칭되는 행사가 없다"도 빈 목록이
아니라 오류 XML로 준다(devlog 15) — 표현 하나("용접공" 자체)가 이 오류를
맞으면 `gather`가 예외를 그대로 전파해 다른 표현("용접")이 찾은 실제 결과까지
통째로 버려졌다.

**수정**: `training_course`의 4-엔드포인트 `_safe`/`any_ok` 패턴과 동일하게,
표현마다 실패를 개별 흡수하고 전부 실패했을 때만 예외를 올리도록 고쳤다
(`fix/job-fair-partial-variant-failure`, PR #83→dev→#84→main).

## 검증 결과

수정 배포 후 "경남 용접공 채용행사"를 재시도하니 4건이 정상적으로 나왔다
(`broadened: true`). 이어서 이미 표에 있는 직업들로 개선폭을 확인했다:

| 질의 | 이전(동의어 확장 전) | 이후 |
|---|---|---|
| 광주 제빵사 훈련과정 | 1건 | **8건** |
| 서울 회계사 훈련과정 | (미측정, 신규) | **8건** |
| 부산 미용사 훈련과정 | (미측정, 신규) | **8건** |
| 경남 용접공 채용행사 | skipped | **4건**(위 회귀 수정 후) |

"바리스타"/"자동차정비사"/"지게차운전기능사"/"산업안전기사"/"조리사"/
"헤어디자이너"/"사회조사분석사"/"그래픽 디자이너"는 표에 없거나 있어도
직역 자체가 이미 실제 과정명과 일치해 8건씩 잘 나왔다 — 이 직업들은 표 확장이
불필요함을 확인했다.

## 새로 발견한 진짜 동의어 격차 2건

**"반려동물미용사"** → 0건. 지역을 뗀 통제 질의로 실제 과정 제목을 보니
"애견미용사"로만 등록돼 있었다("반려견 스타일리스트"라는 표현도 확인). 직역과
실제 자격증 명칭이 완전히 다른 경우다.

**"유치원교사"** → 0건. 같은 방식으로 확인하니 실제 과정은 전부 "보육교사"
(어린이집 교사)로 등록돼 있었다 — 유치원 정교사는 4년제 학위 기반 자격이라
work24 훈련과정 자격증 체계에는 애초에 없고, 보육교사가 이 체계의 실제
용어였다.

두 항목을 `occupation_synonyms.py`에 추가했다:
```python
"반려동물미용사": ("애견미용사", "펫미용사", "반려견 스타일리스트"),
"유치원교사": ("보육교사", "어린이집 교사"),
```
겸사겸사 "통역사"에 "관광통역안내사"(실제 자격증명), "물류창고관리자"에
"물류관리사"(실제 자격증명)를 정밀도 보강 차원에서 추가했다.

## 핵심 관찰

직역이 곧 실제 자격증/과정명인 직업(바리스타, 자동차정비사, 지게차운전기능사,
사회조사분석사 등)은 애초에 동의어 표가 필요 없다 — 이 표의 가치는 **일상
호칭과 자격증 체계의 명칭이 실제로 다른** 소수 직업(용접공→용접기능사,
제빵사→제과제빵, 반려동물미용사→애견미용사, 유치원교사→보육교사)에
집중돼 있다. 앞으로 표를 늘릴 때도 "직역이 이미 통하는지" 먼저 확인하고,
안 통하는 경우에만 추가하는 게 효율적이다.
