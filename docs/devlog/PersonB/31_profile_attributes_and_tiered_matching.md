# 31. 대화 기반 프로필 + 교집합/합집합 티어 매칭

2026-09-11 · 브랜치 `feature/profile-attributes-matching` · 스펙 [docs/specs/profiling_and_matching.md](../../specs/profiling_and_matching.md)

## 요청

사용자를 거의 프로파일링하다시피 정보를 모아 맞춤 취업 정보·혜택을 찾아준다. (1) 대화에서 얻은 정보를 대화에 다시 쓰고 프로필로 저장한다. (2) 사용자 정보의 교집합에 있는 공고를 우선하되 합집합도 찾는다.

결정(사용자 선택): 추정 값은 **자동 저장 + 사후 수정**, 민감정보는 **동의 후에만**, 범위는 **시연(9/16) 전 핵심만**(대화 정교화는 2단계).

## 핵심 결정

- **속성은 문서로 흐르지 않는다.** `draft_answer`에 넣으면 추정 값이 AI 초안에 섞이고 사용자가 "확인"을 누르는 순간 confirmed_fact가 된다. 그래서 주입은 후속·드릴다운 질문 프롬프트뿐이다.
- **조정은 규칙으로.** Mem0는 ADD/UPDATE/DELETE를 LLM이 고르지만, 32b 호출 하나가 수십 초라 규칙으로 줄였다: 같은 값 NOOP / 사용자가 확인·수정한 값 보호 / 추정끼리는 새 값이 옛 값을 무효화(행은 남긴다) / 사용자가 지운 값은 `rejected`로 남겨 **다시 추정해도 되살리지 않는다.**
- **"제한없음"을 명시 일치로 세지 않는다.** 필드 판정을 match/open/unknown/mismatch 넷으로 나눴다. 학력 제한없음이 2,304/2,673건이라 open을 일치로 세면 교집합 칸이 조건 없는 정책으로 도배된다.
- **하드 vs 소프트.** 나이·거주지·혼인이 안 맞으면 신청 자격이 없으니 뺀다(`include_excluded=true`면 맨 뒤). 학력·전공·취업상태는 순위만 내린다.
- **특화분야 "해당한다고 말 안 함"은 불일치가 아니다.** 한부모 대상 정책을 한부모라고 말하지 않은 사용자에게서 빼면, 말할 기회를 준 적도 없는 사람의 자격을 우리가 판정하는 셈이다 → unknown.
- **풀 확대(100 → ~1,000).** 최신 100건만 받으면 사용자 지역·나이에 맞는 정책이 몇 개 안 돼 교집합이 비었다.
- **게스트도 속성을 가진다.** 인터뷰 답변에서 이미 쌓이고 맞춤 추천도 게스트를 받는다. 보고 지울 수단이 있어야 한다. 단 민감 동의는 가입 계정만 — 기기에 묶인 임시 계정은 기기를 잃으면 삭제 수단도 잃는다.

## 트러블슈팅

- **온통청년 코드표가 공개돼 있지 않다** → 전량 집계 후 샘플 대조. 모든 필드에서 가장 흔한 코드가 마지막 번호였고 그게 "제한없음"이었다(화면은 맨 앞, 코드는 맨 뒤). 한부모("청년한부모 자녀양육비")·군인("군복무 상해보험")·기혼("신혼부부 주거자금")처럼 의미가 명확한 샘플로 순서를 확인했다.
- **`sprtTrgtAgeLmtYn`이 거짓말한다** → Y·N 둘 다 19~39 같은 실제 범위와 함께 온다. Y+0/0이 제한없음. min/max만 본다.
- **API 연령이 원문과 한 살 어긋난다**(화순군 원문 18~49, API 17~48) + 사용자는 출생연도만 알아 ±1 → 경계 ±1년은 제외가 아니라 unknown.
- **광주·전남 코드가 사라졌다** → 분포에 29(광주)·46(전남)이 0건이고 12가 13,647건. 샘플이 전부 "전남광주통합특별시". `regions.py`의 "광주(29)는 0건"이라는 기존 의문도 이것으로 설명된다. 매칭 시 29/46 → 12(`REGION_ALIASES`). 고용24용 `regions.py`는 건드리지 않았다.
- **시 코드 vs 구 코드** → 수원은 `regions.py`에서 41110인데 온통청년은 구 단위(41111, 41113…)로 나열. 앞 4자리로 비교.
- **온통청년이 무작위로 한 페이지를 실패시킨다**(세 번 돌려 14·15·2페이지, 400 "api data invalid" / 403 "invalid api key") → 첫 페이지 실패만 오류, 이후는 받은 만큼 유지.
- **API 키가 traceback에 찍혔다** → 진단 스크립트가 `raise_for_status()`를 썼고 httpx 예외 메시지에 요청 URL(쿼리스트링 = 인증키)이 통째로 들어갔다. 같은 경로가 `youthcenter_source.fetch`에도 있었다 — ingest가 예외 문자열을 `feed_refresh_states.last_error`에 저장하고 `/feed/sources`가 로그인 사용자에게 보여주므로 **운영에서 키가 노출될 수 있는 경로였다.** 상태코드를 직접 보고 URL 없는 `YouthCenterApiError`를 `from None`으로 던지게 고쳤고 회귀 테스트를 붙였다. 이번에 찍힌 키는 재발급 권장.
- **원소 하나짜리 튜플 CHECK** → `f"IN {('sensitive_profiling',)}"`이 `('sensitive_profiling',)`로 찍혀 SQL 문법 오류. SQLite 테스트가 먼저 잡았다(Postgres도 같은 오류).
- **alembic이 URL을 못 읽는다** → `env.py`는 `.env`가 아니라 프로세스 환경변수 `DATABASE_URL`을 읽는다. 앱 설정 로더로 환경변수를 채워 실행(URL은 출력하지 않음).
- **실모델 스모크(qwen2.5:3b, 로컬)에서 드러난 것**, 가짜 프로바이더로는 못 보는 것들:
  - 인용의 어미를 바꿔 옮긴다("살고 있고" → "살고 있어요") → 정확 일치만 받으면 참인 사실이 버려진다. 가장 긴 공통 구간 ≥ 60%로 완화.
  - **프롬프트 예시를 베낀다** — 지명 없는 말에 예시의 "수원"과 인용을 그대로 붙였다. 인용 대조가 걸러냈고, 예시를 자리표시 문법으로 바꾸고, 지역·자유 텍스트 값은 **값 자체가 원문에 있어야** 받게 했다.
  - 자유 텍스트를 깨뜨린다("백엔드 개veloper") → 같은 원문 대조로 걸러진다.
  - "파이썬, SQL"을 한 값으로 → 쉼표·가운뎃점으로 쪼갠다.
  - "한부모 가정이라…"에서 아무것도 안 냈다 → 결정적 키워드 안전망이 동의 카드 강조만 켠다(값은 저장하지 않음).
  - 최종: 5개 샘플에서 12개 유지, 11개 정확. 오류 1건은 "정보처리기사 필기만 붙음"을 자격증으로 넣은 것(규칙을 무시) — 서버에서 판별할 방법이 없어 편집 화면에서 지우게 둔다.

## 실데이터 확인 (dev DB, 2026-09-11)

온통청년 재수집 후 활성 정책 702건(10페이지 − 마감·중복) 전부 `eligibility` 채워짐. 가상의 프로필로 티어 분포:

| 프로필 | all(교집합) | some(합집합) | none | excluded |
|---|---|---|---|---|
| 수원 · 2000년생 · 미취업 | 13 | 12 | 9 | 668 |
| 위 + 대학 졸업 · 공학계열 | 14 | 11 | 9 | 668 |
| 광주 · 1996년생 | 32 | 126 | 36 | 508 |

- 교집합 1위: "경기 재도전학교"(만 19~70세 · 수원 거주 · 미취업자). 합집합 예: "경기도 대학혁신플랫폼 지원"(수원·미취업 일치, 대상 중소기업·지역인재는 확인 필요).
- excluded가 큰 건 정상이다 — 온통청년 정책 대부분이 시·군 단위라 다른 지역 정책은 신청 자격이 없다.
- **알려진 한계:** 광주 거주자에게 전남 시·군 정책(영암·나주 등)이 excluded가 아니라 "some · 광주 내 대상 시·군 확인 필요"로 나온다. 광주가 통합 코드 12 안의 일부가 됐는데, 12xxx 중 어느 것이 광주 5개 구인지 아직 확정하지 못해 광역 단위로만 비교하기 때문이다(샘플상 광주 남구 12270, 북구 12300으로 보이나 미검증). 잘못 숨기는 쪽이 아니라 더 보여주는 쪽의 오류라 우선 두었다.
- 브라우저: `e2e/profile-matching.spec.ts`(가입 → /archive에서 거주지·취업상태 입력 → 동의/철회 → 메인 "맞춤 정책" 개인화 응답·교집합 우선) 통과.
