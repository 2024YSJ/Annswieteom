# 온통청년 실연동 — 유추한 스펙이 거의 다 틀렸다

관련 spec: [main_page_feed.md](../../specs/main_page_feed.md)

선행 작업: [25_main_page_feed.md](25_main_page_feed.md)

## 배경

피드를 만들 때 온통청년 인증키가 없어서, 공식 문서에서 유추한 스펙으로 클라이언트를
써두고 파서 테스트는 `xfail`로 달아뒀다. 코드에도 "실 키가 나오면 첫 작업은 curl로
진짜 응답을 받는 것"이라고 적어뒀다. 오늘 키가 발급돼서 그걸 했다.

## 유추가 얼마나 틀렸는가

거의 다 틀렸다.

| 항목 | 유추 | 실제 |
|---|---|---|
| 엔드포인트 | `/opi/youthPlcyList.do` | `/go/ythip/getPlcy` |
| 파라미터 | `openApiVlak`/`pageIndex`/`display` | `apiKeyNm`/`pageNum`/`pageSize`/`rtnType` |
| 응답 포맷 | XML | **JSON** |
| 오류 표시 | `<errMsg>` 류 | HTTP 200 + 본문 `resultCode` |
| 정책 id | 있는지 불명 | `plcyNo` 있음 |
| 필드명 | `polyBizSjnm`, `cnsgNmor`, `rqutPrdCn`... | `plcyNm`, `sprvsnInstCdNm`, `aplyYmd`... |

옛 엔드포인트는 **죽어 있다.** 도메인 루트는 200인데 `/opi/youthPlcyList.do`만
연결이 타임아웃된다. 처음엔 방화벽이나 회선을 의심했는데, 같은 호스트의 다른 경로가
멀쩡히 응답하는 걸 보고 경로 문제로 좁혔다. `/go/ythip/getPlcy`는 파라미터 없이
불러도 400을 주길래(= 살아 있다는 뜻) 거기서 잡았다.

**xfail로 달아둔 판단은 옳았다.** 유추한 XML로 초록 테스트를 만들어놨다면 "검증됐다"는
거짓 신호만 남고, 실제로는 엔드포인트부터 틀린 코드가 배포됐을 것이다. 지어낸 픽스처는
통과해도 아무것도 보증하지 못한다.

## 완료 항목

- `youthcenter_source.py` 전면 재작성 — JSON 클라이언트, `resultCode` 기반 오류 감지,
  실제 60개 필드 중 필요한 것만 매핑.
- 테스트를 **실 응답 그대로**(pageSize=2) 붙여넣은 픽스처로 교체하고 `xfail` 제거.
  7개 통과. 응답 본문에 인증키가 섞이지 않는 것을 확인하고 픽스처로 썼다.
- 실 수집 확인: 청년정책 30건, 전량 임베딩. 정책 피드 총 90건(직업훈련 39 +
  구직자프로그램 21 + 청년정책 30), 전체 187건.

## 핵심 결정 사항과 이유

**분류로 걸러내지 않는다.** 대분류는 일자리/교육･직업훈련/금융･복지･문화/참여･기반/
주거 다섯 가지이고 취업 관련은 절반쯤이다. 그래도 전부 받는다 — 섹션 이름이
"취업 정책"이 아니라 "청년 지원 정책"이고, 공백기 청년에게 월세·금융 지원도 실제로
쓸모가 있다. 대신 분류를 `meta_lines` 첫 줄에 실어 카드에서 바로 구분되게 했다.
취업 관련만 보이게 하려면 `lclsfNm`으로 거르면 되지만 그건 제품 결정이다.

**정렬을 따로 안 한다.** API가 이미 등록 최신순으로 돌려주는 걸 실측으로 확인했고,
정책 피드의 정렬 기준도 최신 등록순이라 그대로 맞는다. 전체 2751건 중 앞쪽 30건만
받는다.

**`plcyNo`를 중복 제거 키로 쓴다.** 워크넷 카테고리 대부분이 못 주는 안정적인 id라,
정책은 문구가 바뀌어도 중복 카드가 생기지 않는다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `/opi/youthPlcyList.do`가 ConnectTimeout | 그 경로가 죽어 있다(도메인 루트는 200) | 살아 있는 `/go/ythip/getPlcy`로 교체 |
| `test_fresh_cache_does_not_schedule_a_refresh` 실패 | 그 테스트가 워크넷 6개 카테고리를 하드코딩해뒀는데, 인증키가 발급돼 소스가 7개가 되자 새 소스는 신선하지 않아 갱신이 예약됐다 | `configured_source_keys()`로 실제 설정 목록을 쓰게 변경 — 이 테스트가 확인하려는 건 "전부 신선하면 예약 안 함"이지 소스 개수가 아니다 |

## 남은 작업

- Render 환경변수에 `YOUTHCENTER_API_KEY` 추가(사용자가 진행).
- 취업 관련 분류만 노출할지는 열린 제품 결정. 필요하면 `lclsfNm` 필터 한 줄이다.
