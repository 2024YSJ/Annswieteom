# 19. 디자인 시스템 통일 (흰 배경 + 브랜드 레드) 및 랜딩 개편

2026-09-09

## 배경

레퍼런스로 받은 [쉬었음청년.com](https://xn--660b983azpcmybz2m.com/)의 화면 문법(sticky 흰
헤더 + blur, 흰 카드 + 얇은 보더 + 아주 옅은 그림자, 이모지 퀵액세스 카드 그리드)을
가져오되, 색은 우리 브랜드 레드를 유지하고 배경은 흰색으로 고정해 달라는 요청.
추가로 "첫 화면에서 바로 서비스로 넘어갈 수 있게" 해달라는 요구가 있었다.

레퍼런스의 실제 CSS 토큰을 받아서 확인한 값:

| 항목 | 레퍼런스 | 우리가 채택한 값 |
|---|---|---|
| 폰트 | Pretendard Variable | 동일 |
| 포인트색 | `#3b82f6` | `#b0202f` (브랜드 레드 유지) |
| 페이지 배경 | `#f8fafc` | `#ffffff` 고정 |
| 카드 | 흰색 + `1px #e2e8f0` | 흰색 + `1px #e7e4de` |
| 그림자 | `0 1px 3px #0000000d` 계열 | 동일 강도로 재정의 |
| 모서리 | 6 / 8 / 12 / 16 | 동일 |
| 히어로 | 연한 블루 그라데이션 | 그라데이션 없이 순백 |

## 결정 사항

**1. 다크모드 제거.** `prefers-color-scheme: dark` 블록을 통째로 지우고
`color-scheme: light`로 고정했다. 색이 반전되면 "문서" 같은 인상이 무너지고,
근거 태그·경고 색의 대비를 두 벌 관리해야 한다.

**2. 토큰 이름은 그대로 두고 값만 바꿨다.** `--surface`, `--border`, `--accent`
같은 이름은 13개 컴포넌트가 이미 쓰고 있어서, 이름을 바꾸면 전부 손봐야 한다.
값만 교체하니 대화 화면·결과 화면이 자동으로 새 팔레트를 따라왔다. 새로 추가한
토큰은 `--body-text`, `--danger`, `--caution-*`, `--cite-*`, `--accent-soft*`,
그림자/모서리/`--header-height`.

**3. 유채색은 셋만.** 브랜드 레드(포인트·에러) + 세이지 그린("기록물 인용" 근거
태그) + 앰버("확인이 더 필요한 문장"). 앰버는 원래 배경만 빨강 계열(`--surface-warn`),
보더·글자는 앰버로 섞여 있어서 앰버로 통일했다 — 오류가 아니라 주의 신호라
에러의 빨강과 달라야 한다.

**4. 에러는 색 있는 글씨가 아니라 면으로.** 브랜드 색 자체가 빨강이라 빨간 글씨만
으로는 "강조"인지 "오류"인지 구분되지 않는다. `.msg-error`(연한 빨강 면 + 보더)를
만들고 인라인 `color: "crimson"` 21곳을 정리했다.

**5. Pretendard는 CDN `<link>`로.** 구글 폰트에 없어서 `next/font`로 못 받는다.
jsDelivr의 동적 서브셋 CSS를 `<link rel="stylesheet" precedence="default">`로
붙였다 — React 19가 `<head>`로 끌어올리고 로드까지 렌더를 막아 폰트 깜빡임이 없다
(`node_modules/next/dist/docs/01-app/01-getting-started/11-css.md`). 실제 쓰인 글자만
잘라 받는 빌드라, Noto Sans KR 4종을 `next/font`로 받던 이전보다 오히려 가볍다.
CDN이 죽으면 Malgun Gothic으로 떨어진다.

**6. 랜딩의 CTA는 버튼이 아니라 플로우 카드 두 장.** "공백기 채우기" / "취업 정보
검색" 카드를 누르면 (필요하면 게스트 로그인까지 해서) 세션을 만들고 대화 화면으로
넘어간다. 클릭 지점을 하나로 모으려고 히어로에 별도 큰 버튼은 두지 않았다.

문구는 후보 3안(공감형 / 기능·직설형 / 브랜드 선언형)을 제시해 브랜드 선언형으로
확정: "우리는 쉬지 않았습니다 / 공백기라 불린 시간을, 근거 있는 커리어 문서로."

**7. 랜딩에 "이렇게 만들어집니다" 섹션 추가.** STAR 4단락 + 문장별 근거 태그가 붙은
예시 문서. 근거 태그 종류는 실제 `confirmed_facts.source_type` 세 가지(사용자 확인 /
사용자 수정 / 기록물 인용)와 일치시켰다.

확정 전 목업: [docs/design/landing-mockup.html](../../design/landing-mockup.html)
(정적 HTML, 토큰 값의 원본 기준으로 남겨둔다)

## 트러블슈팅

**세션 대화 화면에서 대화 맨 위가 헤더 뒤로 숨음**
- 문제: 세션 화면에 들어가면 첫 말풍선 윗부분이 sticky 헤더에 가려짐.
- 원인 두 가지가 겹쳐 있었다. (1) 대화 컨테이너가 `height: 100dvh`인데 그 위에
  64px 헤더가 있어 문서가 뷰포트보다 길어짐. (2) 그 아래 `SiteFooter`와
  `.app-sidebar { min-height: 100vh }`가 각각 더 길이를 보탬. 문서가 길어진 상태에서
  `bottomRef.scrollIntoView()`가 창까지 같이 스크롤시켰다.
- 해결: 대화 컨테이너를 `calc(100dvh - var(--header-height))`로, 사이드바를
  `calc(100vh - var(--header-height))`로 바꾸고, 세션 경로에서는 `SiteFooter`를
  렌더하지 않게 했다(`usePathname`). 대신 Flaticon 라이선스 표기는 세션
  사이드바 맨 아래로 옮겨서 서비스 화면에서 사라지지 않게 했다.

**모바일 세션 헤더에서 글자가 세로로 눌림**
- 문제: 390px 폭에서 "게스트님 / 회원가입하고 저장하기 / 로그아웃"이 사이드바
  토글(☰)과 겹쳐 한 글자씩 세로로 접힘.
- 원인: 토글은 `position: fixed`로 헤더 위에 떠 있는데 헤더는 그 존재를 모른다.
- 해결: 헤더 스타일을 인라인에서 `globals.css`의 `.topbar-*`로 옮기고(미디어 쿼리
  필요), 좁은 화면에서 닉네임을 숨기고 게스트 CTA 라벨을 "회원가입"으로 줄였다.
  토글 자리는 `body:has(.app-shell) .topbar-inner { padding-right: 62px }`로만
  비운다 — 토글이 있는 세션 화면에서만 적용된다.

**사이드바 상태 라벨의 자간이 벌어짐**
- 원인: 상태 라벨에 `.mono`(IBM Plex Mono)를 줬는데 한글 글리프가 없어 대체
  폰트로 떨어짐. 본문 서체로 되돌렸다. `.mono`는 계속 쓰되 라틴 문자/숫자 라벨
  (`TONE: 담백 · v2`, `SITUATION` 같은)에만.

**AI 말풍선이 안 보임**
- `--surface`가 거의 흰색(`#fbfaf9`)이라 흰 배경 위에서 면이 구분되지 않았다.
  시스템 원칙대로 `1px var(--border)` 보더를 함께 줬다.

## 남은 작업 / 확인 필요

- `npm run build`는 이 노트북에서 Turbopack 네이티브 바인딩이 Application Control
  정책에 막혀 실패한다. `next build --webpack`으로는 통과 — 기존 환경 제약이고
  이번 변경과 무관하다.
- E2E는 8개 중 7개 통과. `session-flow.spec.ts`는 단독 실행 시 24.1초로 통과하지만
  전체 스위트를 돌리면 30초 timeout에 걸린다. 실제 백엔드 + 로컬 소형 LLM 응답이
  느려서 생기는 기존 문제로, timeout을 올리거나 스텝을 나누는 게 필요하다.
- `e2e/guest.spec.ts`는 "게스트로 시작하기" 버튼이 사라져서 한 단계 줄여 수정했다.
