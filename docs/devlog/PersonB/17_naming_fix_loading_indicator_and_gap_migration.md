# 이름 통일, "멈춘 것처럼 보이던" 버그, 공백기→취업 정보 검색 이관

관련 spec: 없음(11~16과 동일하게 체크리스트 밖 항목)
날짜: 2026-09-08

---

## 배경

[16번 devlog](16_job_info_search_rewrite.md)로 "취업 정보 종합 검색"을 배포한 뒤 사용자 피드백 3가지: (1) UI 곳곳에 옛 이름 "일자리 찾기"가 남아있음, (2) 대화를 시작하자마자 화면이 멈춘 것처럼 보임 — "내러티브 작성과 같이 코드를 쓴 거 맞지?"라는 정당한 지적과 함께, (3) 공백기 채우기 인터뷰 이후 그 세션 정보를 취업 정보 검색으로 넘길 수 있는 기능 필요.

(2)번 지적이 뼈아팠다 — 직전 재작성 때 e2e 테스트가 `/job-search/query`를 **전부 mock 처리**해서, 실제 로컬 LLM이 관여하는 진짜 왕복을 브라우저로 검증한 적이 없었다. 이번엔 mock 없이 실 백엔드+실 로컬 Ollama로 직접 재현부터 했다.

## 완료 항목

### 1. 이름 통일
"일자리 찾기"가 남아있던 자리(홈 화면 선택 버튼과 설명 문구, 사이드바 그룹 제목, "이 결과로 일자리 찾기 시작" 버튼, e2e 텍스트 전부)를 "취업 정보 검색"으로 통일. 홈 화면 설명 문구도 예전 기능("희망 조건을 알려주시면 채용정보를 찾아 적합도까지 판단해드려요")을 그대로 남겨뒀던 걸 새 기능 설명으로 교체.

### 2. "멈춘 것처럼 보이던" 버그
mock 없이 실 흐름을 Playwright로 직접 재현해보니, `/job-search/query` 요청 자체는 정상적으로 나가고 정상적으로 끝났다(실 데이터까지 받아옴) — 문제는 **로컬 LLM 분류 호출이 수십 초 걸리는 동안 화면에 아무 표시도 없었다는 것**. `JobSearchChatPage.tsx`에 로딩 상태 자체가 없었다. 사용자가 보낸 질문을 즉시 오른쪽 말풍선으로 보여주고, 그 아래 `LoadingNotice`(기존에 Render 콜드스타트 대응으로 만들어둔 컴포넌트, 재사용)를 붙여서 응답이 오기 전에도 "뭔가 진행 중"이라는 걸 알 수 있게 했다.

### 3. 공백기 채우기 → 취업 정보 검색 이관
사이드바의 ✏️(이름 변경)/🗑(삭제) 아이콘 두 개를 "⋯"(더보기) 버튼 하나로 통합하고, 클릭하면 팝업 메뉴(이름 변경/삭제 + 공백기 채우기 세션에서만 보이는 "취업 정보 검색으로 이관")가 뜨도록 바꿨다. "이관"을 누르면:
1. `linked_gap_session_id`를 이 공백기 세션으로 지정한 새 job_search 세션을 만들고 그리로 이동
2. 새 세션에 처음 들어가면 `POST /job-search/draft-query-from-gap`을 자동으로 한 번 호출 — 연결된 공백기 세션의 confirmed_facts를 LLM이 요약해서, 컴포저에 미리 채울 첫 질문 초안("카페 아르바이트 경험이 있는데 관련 직업훈련과정 알려줘" 같은 구어체 문장)을 돌려준다
3. 사용자가 그 초안을 그대로 보내거나 고쳐서 보내야 실제로 검색이 시작된다 — 아무것도 자동 전송/저장되지 않는, 이 앱 전반의 "AI가 쓰고 사용자가 확인" 원칙 그대로

AskUserQuestion으로 "이관"의 정확한 의미(단순 연결+이동만 할지, 초안 질문까지 미리 써줄지)를 확인받고 진행 — 후자로 확정.

새 LLM 능력 `draft_job_info_query_from_facts`(confirmed_facts → 자유 텍스트 질문 초안 하나, `extract_categories`류와 같은 JSON-only 컨벤션) 추가, 새 프롬프트 `draft_job_info_query.jinja`. 급여/근무지처럼 사실만으로 알 수 없는 조건은 절대 지어내지 말라는 지시 포함(다른 모든 프롬프트와 동일한 정직성 원칙).

## 핵심 결정 사항과 이유

**실 LLM을 mock 없이 브라우저로 직접 왕복시켜본 뒤에야 진짜 원인을 알았다.** e2e 테스트에서 네트워크 계층을 mock하는 건 이 프로젝트 전반의 관례(속도/결정성 때문)지만, 이번처럼 "그 자리에서 실제로 뭘 하는지"를 검증해야 할 때는 mock이 오히려 진짜 문제(로딩 상태 없음)를 가려버린다는 걸 다시 확인했다. mock된 e2e는 계속 유지하되(빠르고 결정적이라 회귀 방지엔 여전히 유효), 사용자가 직접 겪은 것과 같은 증상을 재현할 땐 mock을 걷어내고 실 스택으로 확인하는 걸 우선했다.

**이관 시 초안 질문을 자동 전송하지 않고 컴포저에 채워만 둔다.** AskUserQuestion에서 "그대로 보내거나 고쳐서 보내는" 쪽으로 확정된 것도 있지만, 애초에 이 앱 전체가 "AI 초안 → 사용자 확인 후 전송/확정"이라는 하나의 원칙으로 일관되게 동작한다(카테고리 후보, 인터뷰 답변, 문서 문장 전부 동일) — 이번에도 그 패턴을 벗어날 이유가 없었다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 사용자가 "대화 시작하자마자 화면이 굳었다"고 보고 | mock 없는 실 e2e로 재현해보니 요청 자체는 정상 왕복(수십 초 뒤 실 데이터 도착) — 그 사이에 로딩 표시가 전혀 없어서 멈춘 것처럼 보였을 뿐 | `pendingQuery` 상태 추가 — 전송 즉시 질문 말풍선 + `LoadingNotice`를 보여주고, 응답이 오거나 실패하면 지운다 |

## 검증

- 백엔드 신규 테스트 3개(`draft-query-from-gap` — 연결 안 됨 409, 다른 사용자 세션 연결 거부 404, 정상 흐름) 포함 전체 181개 통과.
- 프론트 e2e 신규 파일(`sidebar-session-menu.spec.ts`) — 메뉴를 통한 이름 변경, 이관(새 세션 생성+이동+초안 프리필 확인), job_search 세션엔 이관 메뉴가 없는 것, 삭제까지 한 시나리오로 확인. 2회 연속 통과. 기존 e2e 전체(8개) 회귀 없음 확인.
- eslint/build 클린.
- "멈춘 것처럼 보이던" 버그는 mock 없는 실 스택(로컬 Ollama 포함)으로 직접 재현 후 수정 확인 — 로딩 표시가 질문 전송 즉시 뜨는 것까지 눈으로 확인.

## 남은 작업

- 이관 초안 생성이 실패(LLM 불가 등)해도 조용히 넘어가게 해뒀다(에러 문구 없이 그냥 빈 컴포저) — 사용자가 어차피 직접 입력할 수 있어 의도적으로 조용히 처리했지만, 혹시 너무 조용한지는 실사용 피드백을 봐야 한다.
- `LoadingNotice`의 기본 문구("서버가 잠시 쉬고 있다가...")는 Render 콜드스타트를 염두에 두고 쓴 문구라, 이번처럼 "로컬 LLM이 그냥 느린" 경우엔 정확히 맞는 설명은 아니다 — 커스텀 label로 우회했지만 이 컴포넌트를 더 일반적인 문구로 다듬을 여지는 있다.
