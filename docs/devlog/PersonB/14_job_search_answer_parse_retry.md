# 일자리 찾기 인터뷰: 못 알아들은 답변에 예시 보여주고 다시 묻기

관련 spec: 없음(13과 동일하게 체크리스트 밖 항목)
날짜: 2026-09-08

---

## 배경

[13_job_search_turn_based_preferences.md](13_job_search_turn_based_preferences.md)에서 만든 턴 기반 인터뷰는, 사용자가 자유 텍스트를 보내면 LLM이 그 턴의 필드에 해당하는 값을 뽑아 후보 카드로 보여주는 구조다. 그런데 사용자가 그 질문과 무관하거나 애매한 답을 하면(예: "음... 잘 모르겠어요") LLM이 아무 값도 못 뽑아 빈 후보 카드가 뜨고, 사용자는 그걸 그대로 "다음"으로 넘겨버릴 수 있었다 — 명시적으로 "특별히 없어요"를 누른 것과 구분이 안 되는 채로 조용히 빈 값이 저장되는 셈이다. 사용자 요청: 이런 경우 API(워크넷 검색)에 넘길 값이 무의미해지지 않도록, 예시를 보여주며 형식에 맞게 다시 답해달라고 요구하거나, 애초에 다양한 표현을 더 잘 이해하도록(가공 능력을 키워) 대응하자.

두 방향 다 적용했다.

## 완료 항목

- **추출 프롬프트 강화** (`extract_job_preferences.jinja`): salary_min/max를 "연봉 기준 만원 단위"로 통일해서 뽑도록 명시 — "3천만원"/"월 250만원"(×12 환산)/"3000~4000"/"3000만원 이상"(한쪽만) 같은 다양한 표현을 변환하는 규칙을 예시와 함께 추가. career_years도 "3년차"→3, "신입"→0, "5년 이상"→최솟값 5 규칙 추가. 질문과 무관하거나 이해 불가능한 답변은 "언급 안 됨"과 동일하게(null/빈 값) 처리하라는 지침도 명시.
- **프론트 재질문 UX** (`JobSearchInterviewSection.tsx`): 자유 텍스트 제출 후 추출된 값이 이번 턴 필드에 대해 전부 비어 있으면("특별히 없어요" 버튼으로 명시적으로 건너뛴 것과는 다른 경우), 곧장 편집 가능한 후보 카드로 넘어가지 않고 필드별 예시 문구("백엔드 개발", "마케팅", "물류"처럼... 등)를 보여주며 다시 답하거나 명시적으로 건너뛸 수 있게 함(`isEmptyCandidate`/`exampleHint` 헬퍼, `parseHint` 상태). 같은 자리에서 놓치고 있던 기존 결함도 같이 고침 — 추출 API 호출 자체가 실패(네트워크/서버 오류)했을 때 후보가 아직 없는 상태(`turnValue === null`)에서는 에러 메시지가 화면 어디에도 안 뜨던 문제.
- e2e 신규 테스트(`answer the AI can't parse into this field shows an example and asks again`) — 무관한 답변 → 예시 힌트 노출 + "다음"/편집 입력창 없음 확인 → 제대로 답하면 힌트가 사라지고 정상 진행되는 것까지 확인. 백엔드 185개 + 기존 job-search e2e 포함 전부 통과(2회 연속 재현 확인), eslint/build 클린.

## 핵심 결정 사항과 이유

**새 백엔드 엔드포인트나 응답 필드를 추가하지 않았다.** "값을 하나도 못 뽑았다"는 판단은 이미 `preferences/extract`가 돌려주는 응답(해당 필드가 null/빈 문자열/빈 배열)만으로 프론트에서 충분히 계산 가능하다 — 서버가 "성공/실패" 플래그를 따로 내려줄 필요가 없었다.

**재질문 UX는 이번에도 최초 1회차 인터뷰(`JobSearchInterviewSection`)에만 적용, 확정 후 "조건 수정하기"(`JobSearchPreferencesSection`)는 그대로 뒀다.** 재편집 화면은 `mergeDraft`가 이미 "이번 턴에 언급 안 된 필드는 기존 값 유지"로 비파괴적으로 동작하고, 사용자가 전체 폼을 눈으로 보고 "확인"을 눌러야 저장되므로 무의미한 값이 조용히 API까지 흘러갈 위험이 원래도 낮다 — 반면 최초 인터뷰는 "다음"을 누르는 순간 그 필드가 곧장 `completed_fields`에 편입되므로, 여기서 막는 게 워크넷 검색 파라미터 품질에 실제로 효과가 있다.

## 남은 작업

- 이번 프롬프트 강화(급여/경력 표현 정규화)는 실 LLM(로컬 Ollama/Gemini)으로 다양한 표현을 직접 넣어보는 수동 확인은 아직 안 함 — e2e는 추출 API 자체를 mock했으므로 프롬프트 문구 변경의 실제 효과는 검증 범위 밖.
