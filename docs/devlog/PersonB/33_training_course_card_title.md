# 33. 훈련과정 카드에 과정명 표시

2026-09-11 · 브랜치 `feature/training-course-title`

## 요청

"직업훈련·취업 프로그램" 섹션의 훈련과정 카드가 훈련기관 이름만 보여줘서 무슨 과정인지 알 수 없다 → 과정명이 나오게.

## 원인

`job_info_client._search_one_training_endpoint`가 `subTitle`을 제목으로 쓰고 있었다. 4개 엔드포인트(국민내일배움카드·사업주훈련·컨소시엄·일학습병행) 실응답을 찍어보니 `subTitle`은 **훈련기관명**이고 과정명은 `title`에 따로 온다. 링크도 `subTitleLink`는 기관 소개, `titleLink`가 과정 상세였다. 메타는 비어 있었다(`meta_lines=[]`).

| 필드 | 예시 |
|---|---|
| `title` | 요양보호사자격취득과정 |
| `subTitle` | 평화요양보호사교육원 |
| `traStartDate` / `traEndDate` | 2026-09-11 / 2027-01-10 |
| `titleLink` | …/selectTracseDetl.do?tracseId=… |
| `trprId` + `trprDegr` | AIG20250000524076 · 9 |
| `courseMan` | 880000 |

## 변경

- 제목 = 과정명(`title`, 밑줄은 공백으로 — 일학습병행은 "2026년_(표준형)재직자_…"로 온다), 부제 = 훈련기관, 메타 = 유형·기간·지역·훈련비(0원은 생략), 링크 = 과정 상세.
- `source_key = trprId:trprDegr` — 해시 대신 안정적인 중복 제거 키. 피드는 다음 수집부터 새 키로 들어오고 옛 해시 행은 비활성 → 14일 뒤 정리.
- 여러 지역 조합 결과를 합칠 때 키에 meta를 포함 — 부제가 이제 기관명이라 유형이 다른 과정이 합쳐지지 않게.
- **`_get`의 인증키 노출 경로 차단** — `raise_for_status()`·httpx 예외 메시지에 authKey가 담긴 URL이 들어가고, 피드 수집이 그걸 `last_error`에 저장해 `/feed/sources`로 보여준다(devlog 31의 온통청년과 같은 문제). 상태코드를 직접 보고 URL 없는 `WorknetApiError`로 바꿨다. 부수 효과로 타임아웃도 이제 `WorknetApiError`라 대화형 검색에서 해당 카테고리만 실패 처리된다(예전엔 라우트가 500이 될 수 있었다).
- 대화형 취업 정보 검색도 같은 파서를 쓰므로 LLM 관련성 판단에 과정명·기간이 들어간다.

## 이어서: 맞춤 직업훈련 섹션 (같은 브랜치)

요청: "맞춤형 카드 목록도 공고, 직업훈련, 지원 정책을 보여주도록." 결정(사용자 선택): **맞춤 섹션 3개**(맞춤 공고 / 맞춤 지원 정책 / 맞춤 직업훈련 — 일반 섹션 3개와 대칭), 직업훈련 정렬은 **지역 우선 + 유사도**(훈련은 통학해야 한다).

- 훈련과정의 개설 지역 `trngAreaCd`(시군구 5자리)를 `JobInfoResult.region_code` → `feed_items.eligibility = {"area_code": …}`로 싣는다. 기존 컬럼이라 마이그레이션 없음.
- `matching.rank_by_region`: 거주지·희망지역 안에서 열리는 과정 먼저 → 프로필 벡터 거리 → 최신 → id. **먼 과정도 빼지 않는다**(정책과 달리 훈련은 지역에 자격이 묶이지 않는다). 가까운 이유는 `matched_labels`("수원 거주지역", "희망지역 서울")로 카드에 ✓ 한 줄. 티어 배지는 정책 전용이라 `match_tier="none"`.
- 벡터 거리 조회를 `rank_tiered`와 공유하도록 `_vector_distances`로 뺐다.
- `MatchProfile.desired_region_codes` — 희망 근무지역(다중값). "수도권"은 코드 하나로 못 담아 저장 시 코드가 비는데, 정렬에서는 서울·경기·인천으로 펼친다. 정책 매칭(거주지 기준)에는 쓰지 않는다.
- `GET /feed/trainings/recommended`(인증, 게스트 포함). 지역 속성도 벡터도 없으면 일반 목록 + `no_attributes`.
- 프론트: "🛠️ 맞춤 직업훈련" 섹션, "맞춤 정책" → "맞춤 지원 정책", `no_attributes` 안내 문구를 정책 전용에서 공용으로.

### 광주·전남 코드 — 고용24도 12였다

지역 우선 정렬을 만들며 고용24 훈련과정의 광역 코드를 찍어보니 온통청년과 똑같이 **12(전남광주)** 였다(`srchTraArea1=29` → 0건, `12` → "전남광주 북구" 등 30건, `46` → 잔여 1건). `regions.py`의 광주 29·전남 46 때문에 **대화형 취업 정보 검색에서 광주·전남 질문은 늘 0건 → 조건 없는 전국 재조회로 떨어지고 있었다**(devlog 20의 "광주 29는 0건" 미스터리가 이것). 둘 다 12로 고쳤고, 역변환 라벨은 "전남광주"(통합 전 29/46으로 저장된 사용자 속성도 같은 라벨).
