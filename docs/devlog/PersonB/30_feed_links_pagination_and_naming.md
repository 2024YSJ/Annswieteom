# 공고 상세 링크, 피드 더보기, 결과물 예시 모달, 이름·표기 정리

메인 화면 피드([25](25_main_page_feed.md)/[26](26_main_page_feed_frontend.md)/[27](27_youthcenter_live_integration.md))를 붙인 뒤 남아 있던 마감 작업 5건. 사용자 요청 그대로 옮기면:

1. 프로젝트에 "워크넷"이라 적힌 걸 "고용24"로 바꿀 것

4. 로고 출처가 검색어와 섞여 부적절함 — 정확하게 고칠 것
5. 공고·정책에 "더보기"를 붙여 더 많이 볼 수 있게 할 것

## 핵심 결정

### 이름 변경은 표시 계층에서 멈췄다

화면에 남아 있던 "워크넷"은 `app/page.tsx`의 `aside="워크넷에서 모아왔어요"` **한 줄뿐**이었다. 카드에 붙는 출처 배지는 `FEED_SOURCE_LABELS = {"worknet": "고용24"}`로 이미 고용24였다 — 즉 같은 화면이 위아래로 다른 이름을 말하고 있었다.

`feed_items.source`의 `'worknet'` 값, `WORKNET_*` 환경변수 7개, `WorknetFeedSource`/`WorknetApiError` 같은 식별자는 **일부러 그대로 뒀다.** DB 값을 바꾸려면 CHECK 제약 재생성 + `UPDATE` 마이그레이션을 프로덕션에 돌려야 하고, 환경변수는 Render 대시보드를 손으로 고치는 동안 배포가 깨진다. 얻는 건 없다. 대신 `worknet_source.py` docstring에 `고용24(구 워크넷)`을 한 번 남겨 코드 식별자와 서비스 이름의 연결을 끊지 않았다.

`docs/devlog/`는 손대지 않았다. 날짜가 박힌 과거 기록이고, `15_worknet_api_investigation_and_error_surfacing.md`는 파일명이 다른 문서에서 링크된다.

### 상세 URL은 추측하지 않고 실제 응답과 실제 페이지로 확인했다

`backend/scripts/probe_job_info_fields.py`를 새로 만들어 실 인증키로 `wk/*` 5개 엔드포인트의 첫 항목 필드를 통째로 덤프했다. 결과:

| 카테고리 | 항목 id | 링크 필드 |
|---|---|---|
| 채용행사 | `eventNo` + `areaCd` | 없음 |
| 공채속보 | `empSeqno` | `empWantedHomepgDetail`(기업 채용 페이지) |
| 공채기업정보 | `empCoNo` | `homepg`(기업 홈페이지) |
| 강소기업 | `busiNo` | **없음** |
| 구직자프로그램 | **없음** | 없음 |

채용행사 상세 페이지는 **파라미터 이름이 API 필드명과 다르다** — `eventNo`가 화면에서는 `newsDataSeqno`, `areaCd`가 `eventMegaRegionCd`다. 처음에 `retriveEmpEventDetail.do?eventNo=`로 추측해서 만들어봤더니 404였고, 검색으로 실제 경로를 찾은 뒤 우리 응답의 id 두 건(49160/56, 49086/54)으로 열어 제목이 정확히 일치하는 것을 확인하고 나서 코드에 넣었다.

**강소기업과 구직자프로그램은 링크를 달지 않았다.** 고용24의 강소기업 페이지는 제도 안내일 뿐 기업별 상세가 없고, 응답에도 링크 필드가 없다. 제목을 검색어로 넣은 검색 URL로 보내는 방법도 있었지만 "항상 뭔가는 열리되 그 공고가 아닐 수 있는" 링크라 택하지 않았다 — **안 열리는 링크는 링크가 없는 것보다 나쁘다.**

`JobInfoResult.source_key`를 추가해 위 id들을 피드까지 흘렸다. `dedup.py`가 예고해둔 대로 `compute_dedup_key`는 한 줄도 안 고쳤고, 호출부에서 `source_key`만 넘긴다. 이제 4개 카테고리가 `h:<해시>` 대신 `k:<id>`를 쓰므로 소스가 문구를 한 줄 고쳐도 카드가 복제되지 않는다.

### 더보기를 붙이기 전에 랭킹 버그 3종을 먼저 고쳐야 했다

`ranking.py`의 `if rows:`가 **"질의 실패"와 "이 페이지는 비었음"을 구분하지 못했다.** 1페이지만 보던 동안에는 안 드러났지만 더보기를 붙이는 순간 셋이 한꺼번에 터진다:

1. 개인화 목록 끝을 넘긴 offset에서 `rows == []` → 같은 offset으로 최신순 분기에 떨어져 **이미 본 카드가 다시 나온다.**
2. 그 길로 `api/feed.py`가 `ai_unavailable`을 붙여 **멀쩡한 피드 2페이지에 "AI 서버가 수리 중이예요."** 가 뜬다.
3. `_count()`가 활성 행 전부를 세는데 개인화 질의는 임베딩 있는 행만 본다 → `total`이 부풀어 **갈 수 없는 페이지로 가는 더보기 버튼**이 생긴다.

`RankedFeed.vector_ranking_failed`를 추가해 "정말 터졌을 때"만 고장 안내를 띄우고, 개인화 경로는 `_count_embedded()`로 도달 가능한 행 수를 따로 센다. 임베딩이 아직 없는 정상 상태는 기존 `preparing` 문구를 유지한다.

### 카테고리를 섞지 않으면 링크를 붙인 의미가 없었다

라이브로 확인해보니 "최신 공고" 200건이 `강소기업 0~49 → 공채기업정보 50~99 → 공채속보 100~149 → 채용행사 150~199`로 **카테고리 덩어리**였다. 한 번의 수집이 카테고리를 차례로 넣어 마지막 카테고리의 `first_seen_at`이 제일 최신이기 때문이다. 하필 맨 앞을 차지한 강소기업이 **유일하게 링크를 못 다는 카테고리**라, 링크를 붙여놓고도 더보기를 8번 눌러야 눌리는 카드가 나왔다.

`_interleaved_order()`로 `ROW_NUMBER() OVER (PARTITION BY category ORDER BY first_seen_at DESC, id)` 순으로 라운드로빈 정렬했다. 첫 화면 6장에 네 카테고리가 다 들어오고 그중 4장이 링크다. 페이지네이션이 성립하도록 정렬은 (순번, 수집시각, id) 3단으로 완전히 결정적이다.

**공고에만 적용한다.** 정책 섹션은 부제가 "최신 등록순"이라 순서 자체가 약속이고, 실측상 이미 카테고리가 섞여 있으며 대부분 링크가 있다.

### 수집 상한은 피드 쪽에서만 올렸다

`job_info_client._FETCH_LIMIT = 20`은 **건드리지 않았다.** 이 값은 대화형 취업 정보 검색과 공유되고, 그 목록은 통째로 로컬 LLM 프롬프트에 들어간다(devlog 18/20). 대신 `worknet_source.FEED_FETCH_LIMIT = 50`을 따로 두고 피드 호출에서만 넘긴다. 온통청년은 자기 주석이 "pageSize=100까지 정상"이라 적어둬서 30 → 100으로 올렸다.

훈련과정만 시그니처가 다르다(`limit`이 아니라 조회 조건을 받는다) — 구분 없이 넘기면 `TypeError`로 그 카테고리만 통째로 사라지므로 테스트로 고정해뒀다.

### 결과물 예시: 이 앱 최초의 모달

기존 위치는 랜딩 맨 아래였고 `!hasSessions` 조건이 붙어 있었다. 즉 **"공백기 채우기를 누를까"를 정하는 순간에는 안 보이고**, 세션이 있는 사용자는 아예 접근할 방법이 없었다.

`.flow` 카드 자체가 `<button>`이라 안에 버튼을 중첩할 수 없어서, `.bubble-tip`과 같이 `.flow-wrap`의 형제로 뒀다. 라이브러리가 없으므로 딤 배경은 `.sidebar-backdrop`, 바깥 클릭 닫기는 `app/sessions/layout.tsx`의 오버레이 패턴을 따랐고, 첫 모달인 만큼 Escape 닫기 · 열 때 포커스 이동 · 닫을 때 트리거로 복귀 · `role="dialog" aria-modal` · body 스크롤 잠금을 직접 넣었다.

### 로고 출처

Flaticon이 복사해주는 크레딧 조각을 그대로 붙여넣은 게 원인이었다. 그건 표기가 아니라 **검색 결과 문구**다:

- 화면에 `아이콘 제작: 침대가 없다 아이콘 제작자: juicy_fish - Flaticon`으로 나와 "아이콘"과 "제작"이 두 번씩 겹쳤고, 검색어였던 "침대가 없다"가 공백기 서비스에 아무 맥락 없이 떠 있었다.
- 링크 `https://www.flaticon.com/kr/free-icons/-` 는 한국어 검색어가 슬러그로 변환되지 않아 하이픈만 남은 **죽은 주소**였다.

라이선스가 요구하는 건 제작자 이름과 Flaticon 링크뿐이므로 `아이콘 제작: juicy_fish · Flaticon`으로 줄이고, 링크는 검색 페이지가 아니라 아이콘 자체 페이지(`free-icon/no-bed_13322151`, 원본 파일명의 id)로 걸었다. `IconAttribution` 한 곳을 고치면 푸터와 세션 사이드바가 같이 고쳐진다. 같은 문자열이 복제돼 있던 `README.md`와 `logo/generate_icons.py` 주석도 갱신하고, "이 조각을 그대로 쓰지 말 것"을 남겼다.

## 트러블슈팅

**추측한 상세 URL이 404** → `retriveEmpEventDetail.do?eventNo=49160`이 404. 원인: 화면 파라미터 이름이 API 필드명과 다름. 해결: 실제 경로(`retrieveEmpEventDtl.do?newsDataSeqno=&eventMegaRegionCd=`)를 찾아 우리 데이터로 두 건 열어보고 확정.

**프로브 스크립트가 `UnicodeEncodeError: 'cp949'`** → Windows 콘솔 기본 코드페이지. `PYTHONIOENCODING=utf-8`로 실행.

**Next 개발 서버가 자기 JS 청크에 403** → 브라우저 검증이 "불러오는 중..."에서 멈췄다. 원인 둘: (1) `npm run build`가 `next dev`와 `.next/`를 공유해 실행 중인 개발 서버 상태를 덮어썼다 — 개발 서버 재시작 필요. (2) 그 뒤에도 `127.0.0.1:3000`으로 접속하면 청크가 403인데 `localhost:3000`은 정상이다(Next 16의 개발 서버 cross-origin 가드). **브라우저 검증은 `localhost`로 할 것.**

**예시 버튼이 아래 문단 위에 겹쳐 그려짐** → `.flow`가 `height: 100%`로 그리드 행 전체를 먹어 형제 버튼이 래퍼 밖으로 밀려났다. `.flow-wrap`을 flex column으로 만들고 `.flow`를 `flex: 1`로 바꿔 해결. 좌표로 겹침 없음을 wide/narrow 두 폭에서 확인.

## 검증

- `pytest` 365건 통과(신규 13건: 랭킹 7, 고용24 소스 어댑터 3, 파서 3).
- `npm run lint` / `tsc --noEmit` / `npm run build` 통과.
- **실 API 라이브 확인**: 채용행사 상세 링크가 실제로 해당 행사 페이지를 연다(제목 일치 2건).
- **실 DB 페이지네이션**: 공고 200건을 6건씩 끝까지 넘겨 중복 0, 누락 0.
- **브라우저 확인**(`localhost:3000`): 이름 표기, 푸터 표기·링크, 모달 열기/Escape/포커스 복귀, 첫 화면 6장 중 4장 링크, 더보기 증가와 중복 없음 — 17개 항목 전부 통과.

## 남은 작업

- **강소기업·구직자프로그램은 여전히 링크가 없다.** 고용24가 항목별 공개 상세를 제공하지 않는 한 방법이 없다. 다른 소스(예: 국민취업지원제도 포털)를 붙이면 풀 수 있다.
- 공채속보/공채기업정보의 상세 링크는 고용24가 아니라 **기업이 직접 운영하는 페이지**다. 기업이 채용을 마감하고 페이지를 내리면 링크가 죽는데, 지금은 감지하지 못한다.
- 이번에 수집 상한을 올리면서 카테고리당 30건이 한꺼번에 새로 들어왔다. 프로덕션에 배포하면 같은 백필이 한 번 일어난다(설계된 동작 — 옛 행은 `is_active=False`로 내려가고 14일 뒤 정리).
- 모달에 포커스 트랩(Tab 순환 가둠)은 없다. Escape·바깥 클릭·✕로 닫히고 포커스가 복귀하므로 갇히지는 않지만, 모달을 하나 더 만들게 되면 공용 컴포넌트로 빼면서 같이 넣는 게 좋다.
