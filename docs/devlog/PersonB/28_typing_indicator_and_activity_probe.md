## 배경

프로덕션 사용 중 나온 세 가지를 한 번에 처리했다.

## 1. 대기 표시 통일

사용자 피드백: "말풍선이 생겼다가 사라지니까 이질적이네."

조사해보니 대기 표시가 **세 갈래로 제각각**이었다 — 카테고리는 `찾는 중...` 맨텍스트 버블, 인터뷰는 muted span, 취업정보/결과는 `LoadingNotice`. 게다가 전부 정적 텍스트라 버블이 툭 생겼다 툭 사라졌다. **기록물 등록 단계는 아예 아무 표시도 없었다** — 텍스트나 파일을 보내면 버튼만 비활성화되고 화면은 그대로라, 직전에 카테고리 단계에서 고쳤던 "먹통처럼 보이는" 문제와 같은 상태였다.

- `components/TypingDots.tsx` 신규 — 점 세 개가 시차를 두고 튄다. `role="status"` + `aria-live`로 스크린 리더에도 알린다.
- `globals.css`에 `.typing-dots`/`.typing-dot` + `@keyframes typing-bob`. **애니메이션만은 인라인으로 못 쓴다** — 채팅 컴포넌트는 전부 인라인 스타일 + CSS 변수를 쓰지만 `@keyframes`는 예외이고, 그 선례가 `.bubble-tip`/`bubble-bob`이다. 점 크기 5px은 `.chip::before`와 맞췄다.
- `LoadingNotice`는 라벨 옆에 점을 붙이는 형태로 바꿨고 **4초 콜드스타트 안내는 그대로 뒀다** — Render 프리티어가 15분 유휴 후 잠드는 실제 문제를 설명하는 문구이고 호출부 7곳이 그 동작에 의존한다.
- 카테고리/인터뷰/기록물에 적용. 취업정보·결과는 `LoadingNotice`를 쓰므로 호출부 변경 없이 따라왔다.

마운트/언마운트 **지점은 건드리지 않고 내용물만 교체**했다. `CategorySection`의 두 분기가 `!isExtracting`으로 물려 있고 `JobSearchChatPage`의 스크롤 effect가 `pendingQuery`에 의존해서, 지점을 옮기면 교체 타이밍과 스크롤이 같이 바뀐다.

## 2. 카테고리 단계에서 AI가 되묻기

직전 수정(devlog 없음, `edf80af`)으로 "잘 모르겠어"에 화면이 멈추는 건 고쳤지만 정적 예시 나열이었다. 사용자 요청은 **사이트가 먼저 질문을 던지는 것**이었다.

- 새 LLM 능력 `probe_activity_question(free_text, gap_start, gap_end, focus)` + `probe_activity_question.jinja`.
- `POST /categories/extract` 응답에 `followup_question`을 더했다. **엔드포인트를 새로 만들지 않았고, LLM 호출은 suggestions가 빈 경우에만** 일어난다 — 정상 경로 비용은 그대로다.
- 실패하면 `None`을 돌려주고 프론트가 기존 정적 예시로 되돌아간다. "직접 입력할게요" 버튼은 어느 쪽이든 남는다 — 되물어도 계속 모르겠다는 사용자가 막히면 안 된다.

### 갈래 선택을 LLM에서 코드로 가져온 이유

처음엔 프롬프트에 갈래 목록을 주고 모델이 고르게 했다. 14b 실측 결과 **입력이 뭐든 "아르바이트"만** 물었다. "매번 아르바이트만 묻지 마라"를 넣었더니 이번엔 **전부 "운동/건강"**으로 쏠렸다 — 쏠리는 갈래만 바뀐 것이다.

그래서 `PROBE_FOCUSES` 7개를 `llm/base.py`에 두고 **서버가 `random.choice`로 고른 뒤 LLM에는 문장 만들기만 시킨다.** 다양성이 보장되고, 같은 사용자가 계속 "모르겠다"고 해도 매번 다른 각도로 물어본다. 7개 갈래 전부 14b로 확인했다:

> "그 기간 동안 아르바이트나 단기로 일하신 적 있으신가요?"
> "그 기간 동안 즐겨 하시던 취미나 관심사가 있으셨나요?"
> "지원서를 쓰거나 면접을 본 적 있으신가요?"

**로컬 3b에서는 품질이 안 나온다.** `잘 모르겠어` → `"쉬었다면요?"` 수준이고, 갈래를 고정한 뒤에도 `"가족 돌봄이나 집안일 **외에** 무엇 하셨나요?"`처럼 지시를 뒤집는다. CLAUDE.md가 경고하는 그대로이며 운영은 14b라 문제없지만, 로컬에서 이 기능을 눈으로 확인할 때는 터널을 봐야 한다.

## 3. 피드 소스 진단 엔드포인트

사용자 제보: "청년API 정보가 안 가져와지고 있어." 프로덕션을 직접 호출해보니 **정반대였다.**

| | 결과 |
|---|---|
| `/feed/policies` | total=30, 전부 `youthcenter` — 청년API는 정상 |
| `/feed/jobs` | **total=0** — 워크넷 전부 없음 |

Render에 `YOUTHCENTER_API_KEY`만 있고 워크넷 키 7개가 없었다. 코드 문제가 아니었다.

문제는 **그걸 알아내려고 프로덕션 API를 손으로 쳐야 했다는 것**이다. 키 없는 소스를 조용히 스킵하는 건 의도한 설계지만(승인 대기 중인 키 때문에 배너가 뜨면 안 된다), 그 대가로 밖에서 "설정 안 됨"과 "호출 실패"를 구분할 수 없었다.

`GET /feed/sources`(인증 필요) 추가. 소스×카테고리별로 `configured` / `last_succeeded_at` / `last_failed_at` / `last_error` / `active_item_count`를 돌려준다. **`configured=false`인 소스도 목록에 남긴다** — 빠진 소스가 목록에서도 사라지면 "설정 안 됨"과 "그런 소스 없음"이 또 구분되지 않는다.

이 엔드포인트는 원래 스펙의 "자를 순서 1번"이었고 실제로 잘랐다. 잘라서 대가를 치렀으므로 되살렸다.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 되묻기가 매번 같은 갈래로 쏠림 | 모델에게 갈래 선택을 맡김 | 선택을 서버로(`PROBE_FOCUSES` + `random.choice`) |
| 로컬 e2e에서 회원가입이 전부 실패 | 다른 세션이 3000을 점유해 내 dev 서버가 3001로 밀렸는데 백엔드 CORS 기본값이 `localhost:3000`뿐 | 기동 시 `CORS_ALLOW_ORIGINS`에 3001 추가. 코드 문제 아님 |

## 남은 작업

- **Render에 워크넷 키 7개 추가**(사용자). 넣으면 다음 피드 요청이 수집을 예약한다.
- 배포 후 `GET /feed/sources`로 실제로 들어갔는지 확인 — 이번 진단을 URL 하나로 대체하는 게 이 엔드포인트의 목적이다.
