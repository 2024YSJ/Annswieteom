# 63. 구직정보(고용24) API 상태 정정 — "기능 자체를 못 쓴다"는 결론은 해소됨 (2026-09-17)

프로젝트 마감 점검 중 발견한 문서 오류 정정. [15번 devlog](15_worknet_api_investigation_and_error_surfacing.md)의
"남은 작업" 1번이 "이 기능 자체가 지금 상태로는 못 쓴다(사용자 결정 필요)"로
끝나 있어, 이후 devlog를 안 읽으면 job search/main page feed 기능 전체가
막힌 것으로 오해하기 쉽다. 실제로는 그 뒤로 해소됐다.

## 실제 경과

- 15번 devlog가 막혔다고 확인한 것은 `callOpenApiSvcInfo210L01.do`
  (채용정보 검색) **단 하나의 엔드포인트**였다 — 개인회원 계정을 구조적으로
  거부하는 기업회원 전용 API. 이건 지금도 막혀 있고, 앞으로도 기업회원
  전환 없이는 못 쓴다.
- [16번 devlog](16_job_info_search_rewrite.md)가 job search 기능 전체를
  **개인회원도 쓸 수 있는 다른 9개 고용24 엔드포인트** 기준으로 다시
  작성했다: 채용행사(`wk/210L11`), 공채속보(`wk/210L21`),
  공채기업정보(`wk/210L31`), 강소기업(`wk/216L01`),
  구직자프로그램(`wk/217L01`), 훈련과정(`hr/310L01`~`313L01`). `210L01`은
  더 이상 코드 경로 어디에서도 호출되지 않는다.
- 별도로 발급받은 7개 키가 모두 라이브로 검증됐고(각 카테고리가 실제
  데이터를 반환), main page feed가 이 데이터로 채워지고 있다.
- 2026-09-12에 사이트 전체 점검(고용24 쪽 장애)이 있었는데, 그 원인 조사
  과정에서 코드 결함 2건이 함께 발견됐다: `job_info_client._safe()`가
  엔드포인트 실패를 조용히 `[]`로 뭉개서 "조건에 맞는 과정 없음"과
  "고용24가 오류를 냄"이 화면에서 구분되지 않던 문제. `job_info_client.py`의
  `_safe` 헬퍼들(훈련과정/채용행사 키워드 변형)이 이제 성공 여부를
  `(결과, bool)`로 함께 반환하도록 고쳐져 있고, 코드 주석에 "2026-09-12까지는
  실패도 성공도 똑같이 `[]`로 뭉개졌다"고 과거형으로 남아 있어 **이미
  해결된 상태**임을 코드 자체가 증언한다.
- 이후 2026-09-15에 실계정 재현 사례(경남 용접공 검색이 한 표현의 실패로
  카테고리 전체가 skipped 처리됨)에 대한 추가 수정도 `job_info_client.py`
  주석에 남아 있다.

## 정정 결론

**job search / main page feed 기능은 막혀 있지 않다.** 유일하게 막힌 것은
채용정보 검색 API `210L01`(기업회원 전용)뿐이며, 이 기능은 애초에 다른
9개 엔드포인트로 대체 구현되어 사용 중이다. 15번 devlog의 "남은 작업" 절은
그 시점(2026-09-08) 기준으로는 정확했지만, 이후 항목을 갱신하지 않아 지금
기준으로는 오해의 소지가 있다 — 15번 원문은 그대로 두고(당시 조사 기록으로서
가치가 있음) 이 파일로 최신 상태를 정정한다.
