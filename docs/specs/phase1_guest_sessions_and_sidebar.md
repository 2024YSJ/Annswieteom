# Phase 1 — 게스트 세션 + 세션 목록 사이드바

Claude-Desktop형 UI 재설계(4단계 로드맵)의 첫 단계. 로드맵 전체와 확정된 제품 결정 사항은 이 문서가 아니라 계획 승인 시점의 대화 기록에 있다 — 여기서는 Phase 1 자체의 설계와 실제 구현 결과만 다룬다.

## 목표

1. 회원가입 없이 세션을 1개까지 체험할 수 있는 게스트 모드
2. 게스트가 회원가입하면 그 세션이 끊김 없이 계정에 이어붙음
3. 로그인 상태에서 우측 사이드바로 자신의 세션 목록을 보고 전환할 수 있음
4. 좌상단에 항상 로그인/회원가입(또는 로그인된 사용자 정보) UI가 떠 있음

## 핵심 설계 결정: 게스트 = `is_guest=True`인 평범한 User

게스트를 별도의 인증 체계나 "세션에 user_id 없이 떠 있는" 특수 상태로 만들지 않고, 기존 `users` 테이블의 평범한 행(email/password_hash가 `NULL`, `is_guest=True`)으로 만든다.

이렇게 하면:
- 기존 JWT 발급, 리프레시 쿠키, `get_owned_session` 소유권 검사 코드를 전혀 안 건드리고 재사용
- "회원가입 시 세션이 이어붙는다"는 요구사항이 데이터 이관 없이 **그 User 행에 email/password를 채우고 `is_guest`만 끄는 것**만으로 해결됨 — `sessions.user_id`가 가리키는 행 자체가 안 바뀌므로 세션·토큰·쿠키가 전부 그대로 유효

JWT 액세스 토큰은 `user_id`만 담고(email/is_guest 등 클레임 없음), 리프레시 토큰도 `user_id`로만 연결되므로, 게스트 행을 제자리에서 업그레이드해도 기존 토큰이 즉시 무효화되지 않는다 — 재로그인 없이 그대로 이어진다.

## 데이터 모델 변경

`users` 테이블:
- `email`, `password_hash`: `NOT NULL` → `NULL` 허용 (Postgres/SQLite 모두 `UNIQUE` 제약에서 `NULL`끼리는 충돌하지 않음)
- `is_guest BOOLEAN NOT NULL DEFAULT false` 추가

마이그레이션: `backend/app/db/migrations/versions/<hash>_add_guest_users.py`

## API 변경

| 엔드포인트 | 변경 내용 |
|---|---|
| `POST /auth/guest` (신규) | 게스트 User 생성 + `/auth/login`과 동일하게 토큰 발급·리프레시 쿠키 설정 |
| `POST /auth/register` (수정) | 인증 안 된 요청은 기존과 동일. **게스트로 인증된 요청**이면 새 행을 만들지 않고 그 행을 email/password/nickname으로 채우고 `is_guest=false`로 전환("업그레이드"). 이미 정회원으로 인증된 요청은 `409 already_registered` |
| `POST /sessions` (수정) | 게스트가 이미 세션을 1개 이상 갖고 있으면 `409 guest_session_limit_reached` |
| `GET /sessions` (신규) | 현재 사용자의 세션 목록을 최신순으로 반환 (사이드바용) |

`register`가 게스트 여부를 판별하려면 인증이 "있어도 되고 없어도 되는" 의존성이 필요해서 `get_current_user_optional`을 추가했다 — 헤더가 아예 없으면 `None`, 헤더는 있는데 토큰이 무효/만료면 (조용히 익명 취급하지 않고) 기존과 동일하게 401을 던진다. 이래야 30분 지나 만료된 게스트 토큰으로 회원가입을 시도했을 때, 그걸 놓치고 새 익명 계정을 만들어버리는(게스트의 기존 세션을 고아로 만드는) 사고를 막을 수 있다 — 프론트의 기존 401→refresh→재시도 로직이 자동으로 새 토큰을 받아온 뒤 재시도하므로 사용자는 이 과정을 눈치채지 못한다.

## 프론트엔드

- 루트 레이아웃에 항상 떠 있는 좌상단 인증 위젯 (로그아웃: 로그인·회원가입 링크 / 로그인: 닉네임 + 로그아웃, 게스트면 "회원가입하고 저장하기" 링크 추가)
- `frontend/app/sessions/layout.tsx`: 기존 5개 세션 페이지를 감싸는 새 레이아웃, 우측에 세션 목록 사이드바. 각 항목은 `pathForStatus()`로 그 세션이 실제로 있는 단계로 이동(하드코딩 금지)
- 랜딩 페이지: 비로그인 상태에서 "게스트로 시작하기" 버튼 추가 (이미 로그인된 사용자가 실수로 두 번째 게스트 정체성을 만들지 않도록 `!isLoading && !user`일 때만 노출)

## 의도적으로 처리하지 않은 것 (Phase 1 범위 밖)

- 게스트가 등록 안 하고 이탈한 세션의 정리(cleanup) — 데이터 보존 정책은 나중 이슈
- 쿠키 삭제로 게스트가 새 정체성을 얻어 다시 체험 가능 — 완전 차단이 목표가 아니라 회원가입 유도가 목표이므로 허용
- "동시에 1개"로 해석 — 유일한 세션을 삭제하면 다시 1개 만들 수 있음 ("평생 1회"가 아님)
